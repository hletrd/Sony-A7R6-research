# A7R VI firmware 1.02

## Release status

On 2026-11-25, Sony's Japan, US, and South Korea listings showed 1.02 as the latest ILCE-7RM6 body firmware. Sony released it on 2026-10-21. The update extends Preset Focus to compatible lenses without power zoom, fixes periodic monitor wakeups and an intermittent movie-mode manual-focus failure, and improves stability. [Sony Japan release notes](https://support.sony.jp/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/software/00413256) · [Sony Japan downloads](https://support.sony.jp/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/downloads) · [Sony US downloads](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/downloads) · [Sony Korea downloads](https://www.sony.co.kr/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/downloads)

## Package identity and analysis

**Direct observation.** The complete Sony Japan `BODYDATA.DAT` was 338,327,032 bytes. Its locally calculated SHA-256 was `831fa09a2839840cd0066fec2cc7ad68c0bb574ecd28ecd4305a64690eb454e9`, which matched the local `A7R6_1.02.DAT`. `cmp -s` also returned `0`. This confirms the package identity through Sony's distribution. The comparison covers the Japanese download. The other listings were checked for release status, and the region code of the user's camera remains unconfirmed. [Firmware manifest](../../data/firmware-manifest.json)

The unmodified `a7iv` branch of [DavidBuchanan314/fwtool.py](https://github.com/DavidBuchanan314/fwtool.py/tree/3955d7890fc38daf942bb52827599bfe35de4a14) was still at `3955d7890fc38daf942bb52827599bfe35de4a14`, also the head of [PR #52](https://github.com/ma1co/fwtool.py/pull/52). The run used macOS 27.2.1 arm64, CPython 3.14.2 managed with uv 0.13.5, pycryptodomex 3.24.1, and PyYAML 6.0.3.

Both packages passed the UFU CRC check in `dat.readDat()`, and `dat.readChunks()` ended at each file's exact length. Both had the same `DATV` and `PROV` payloads (`01000000`). The `UDID` descriptor counts explain the difference in FDAT header offsets. The R5 control is the 4.00 file identified by SHA-256 in the manifest. [DAT parser at the tested commit](https://github.com/DavidBuchanan314/fwtool.py/blob/3955d7890fc38daf942bb52827599bfe35de4a14/fwtool/sony/dat.py)

| Observation | A7R VI 1.02 | A7R V 4.00 |
| --- | ---: | ---: |
| Normal USB descriptors | 4 | 10 |
| Updater USB descriptors | 1 | 1 |
| FDAT header offset in bytes | 84 | 132 |
| FDAT payload size in bytes | 338,326,928 | 754,525,456 |

The R6 unpack command exited `1` with `No decrypter found` and left a zero-byte `firmware.fdat`. A SHA-256 check after the run matched the pre-run hash. The R5 extraction result comes from the earlier [November 5 run](2026-11-05-fwtool-a7iv.md). The R6 failure leaves the FDAT model ID, version field, encryption details, and extracted contents unverified. Repacking, signature validation, installation, and runtime behavior remain unverified.

### Reproduction

Run from a local analysis workspace containing the pinned `fwtool` at `sources/fwtool`, its `uv` environment at `.venv`, and the local copy named `A7R6_1.02.DAT`. Use a fresh directory for each run.

```sh
set -e
result_dir=$(mktemp -d)
curl --proto '=https' --proto-redir '=https' -fsSL \
  -o "$result_dir/BODYDATA.DAT" \
  'https://support.d-imaging.sony.co.jp/download/NEX/by48483927/BODYDATA.DAT?fm=jp'
test "$(stat -f %z "$result_dir/BODYDATA.DAT")" = 338327032
shasum -a 256 "$result_dir/BODYDATA.DAT" A7R6_1.02.DAT
cmp -s "$result_dir/BODYDATA.DAT" A7R6_1.02.DAT
.venv/bin/python sources/fwtool/fwtool.py unpack \
  -f "$result_dir/BODYDATA.DAT" -o "$result_dir/unpacked"
```

## Published source components

**Direct observation.** Sony lists 60 source archives for 1.02, 60 on its unversioned R6 page, and 42 for R5 4.00. Comparing archive basenames, 1.02 replaces three GStreamer 1.18.6 entries with the corresponding 1.26.3 entries and replaces `SRT.tar.gz` with `srt-1.5.6.tar.gz`. The old SRT filename carries no version. The R5 4.00 catalog also lists GStreamer 1.18.6. These are source distribution records. The exact components built into `BODYDATA.DAT` and their relationship to the release-note fixes remain unverified. [R6 1.02 catalog](https://oss.sony.net/Products/Linux/DI/ILCE-7RM6_Ver102.html) · [Unversioned R6 catalog](https://oss.sony.net/Products/Linux/DI/ILCE-7RM6.html) · [R5 4.00 catalog](https://oss.sony.net/Products/Linux/DI/ILCE-7RM5_Ver400.html)

The three `linux-kernel.tar.gz` archives passed `gzip -t`. The sizes and SHA-256 hashes below identify the complete source downloads. Read the kernel version from `linux-kernel/Makefile` with `tar -xOzf linux-kernel.tar.gz linux-kernel/Makefile`.

The two R6 archives have different archive hashes. A streaming comparison with Python `tarfile` found the same 60,683 regular-file paths and the same SHA-256 at every path. The 4,259 other entries matched by path, type, and link target. The comparison covered file contents and paths. Archive timestamps, ownership, permissions, and ordering were outside that comparison.

## Service access and menu language

**Direct source observation.** PMCA-RE Reloaded's `main` matched `v1.15.1` at `28dfca5a37066cb318fb4557d2afdaa781f738a7`. Its service authentication code still returns `SenserV2Unsupported` for a Senser v2 response. The compatibility table marks `ILCE-7RM6` as disputed. Its offline photo metadata code includes the R6 in the mechanical shutter count decoder. [Release tag](https://github.com/masterflai/pmca-re-reloaded/releases/tag/v1.15.1) · [Authentication code](https://github.com/masterflai/pmca-re-reloaded/blob/28dfca5a37066cb318fb4557d2afdaa781f738a7/crates/pmca-usb/src/senser.rs#L403-L420) · [Compatibility table](https://github.com/masterflai/pmca-re-reloaded/blob/28dfca5a37066cb318fb4557d2afdaa781f738a7/crates/pmca-app/src/devices.rs#L529-L535) · [Photo metadata code](https://github.com/masterflai/pmca-re-reloaded/blob/28dfca5a37066cb318fb4557d2afdaa781f738a7/crates/pmca-core/src/photo.rs#L273-L290)

**External reports.** The PMCA-RE Reloaded maintainer attributes Senser v2 to the R6. An August 4 service-provider comment in Sony-PMCA-RE issue #722 claims English-menu support for the Japanese R6 without a procedure or technical evidence. Searches for `ILCE-7RM6`, `A7R VI`, and `A7RVI` in public firmware and PMCA sources did not establish a reproducible English-menu unlock on 1.02. This review used source code and official files only. USB responses and behavior on the user's camera remain unverified. [Maintainer device notes](https://github.com/masterflai/pmca-re-reloaded/blob/28dfca5a37066cb318fb4557d2afdaa781f738a7/crates/pmca-app/src/devices.rs#L316-L324) · [Sony-PMCA-RE issue #722](https://github.com/ma1co/Sony-PMCA-RE/issues/722)
