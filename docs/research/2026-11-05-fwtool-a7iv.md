# fwtool a7iv validation

## Inputs and environment

On 2026-11-05, unmodified `fwtool.py` was run against two user-provided files. Their initial filenames were swapped, so the names were exchanged after execution. SHA-256 hashes were verified to be unchanged by renaming.

| Current filename | Original filename | Size |
| --- | --- | --- |
| `A7R5_4.00.DAT` | `A7R6_1.02.DAT` | 754,525,608 bytes |
| `A7R6_1.02.DAT` | `A7R5_4.00.DAT` | 338,327,032 bytes |

SHA-256 hashes are recorded in the [firmware manifest](../../data/firmware-manifest.json). Hashing started after copying finished and the UFU chunks were complete through `DEND`. File size and modification time remained unchanged during execution. Both inputs passed the container CRC check in `dat.readDat()`.

## Reproduction

Place the two inputs with matching hashes under `inputs/`. These commands use the corrected filenames. The original run used the filenames before they were exchanged.

```sh
git clone --branch a7iv https://github.com/DavidBuchanan314/fwtool.py.git fwtool
git -C fwtool checkout 3955d7890fc38daf942bb52827599bfe35de4a14
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python pycryptodomex==3.24.1 PyYAML==6.0.3
.venv/bin/python fwtool/fwtool.py unpack -f inputs/A7R5_4.00.DAT -o artifacts/A7R5_4.00
.venv/bin/python fwtool/fwtool.py unpack -f inputs/A7R6_1.02.DAT -o artifacts/A7R6_1.02
```

Dependency versions are pinned to reproduce this experiment. `pyinstaller` is used for executable distribution and was not installed for this source execution.

## Observations

| Item | A7R V 4.00 | File inferred to be A7R VI 1.02 |
| --- | --- | --- |
| UFU magic | `895546550d0a1a0a` | `895546550d0a1a0a` |
| DATV payload | `01000000` | `01000000` |
| FDAT chunk header offset | `84` | `132` |
| FDAT payload size | `754525456` | `338326928` |
| Exit code | `0` | `1` |
| Decryption | `CXD90057_k8` | `No decrypter found` |
| Internal model ID | `0x11030080` | Unverified |
| Internal version | `4.00` | Unverified |

The A7R V input produced `firmware.fdat`, `firmware.tar`, `updater.img`, `config.yaml`, and recursively extracted files. The model ID and version in `config.yaml` match the PR's A7R V report. The file size matches [Sony's A7R V 4.00 release information](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm5/software/00292267). These are direct observations.

The smaller input matches the size in [Sony's A7R VI 1.02 release information](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/software/00413269). Its internal model and version could not be verified because decryption failed. Classification as A7R VI 1.02 is an inference based on the official size and the supplied context.

All 12 registered decryption candidates failed the first-block checksum check on this file. The tool exited with `No decrypter found` and did not extract its contents. The empty `firmware.fdat` created during the attempt is not a successful output.

## Conclusion and limitations

This commit extracts the verified A7R V 4.00 input. Its current implementation and keys did not extract the input inferred to be A7R VI 1.02. The PR's [external report dated 2026-10-22](https://github.com/ma1co/fwtool.py/pull/52#issuecomment-6344060460) also lists the A7R VI 1.02 key as unknown.

The failure does not distinguish a key change from a block-format change. No SHA-256 comparison with an official download was performed; a matching size and valid CRC do not prove identity with the official release. This experiment did not validate device execution, repacking, signature bypass, or installation.
