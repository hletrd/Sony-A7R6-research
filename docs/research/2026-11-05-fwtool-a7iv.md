# fwtool a7iv 검증

## 입력과 환경

2026-11-05에 사용자가 제공한 두 파일에 수정하지 않은 `fwtool.py`를 적용했다. 최초 파일명이 서로 바뀌어 있어 실행 후 이름을 교환했다. 이름 변경 전후의 SHA-256이 같음을 확인했다.

| 현재 파일명 | 최초 파일명 | 크기 |
| --- | --- | --- |
| `A7R5_4.00.DAT` | `A7R6_1.02.DAT` | 754,525,608 bytes |
| `A7R6_1.02.DAT` | `A7R5_4.00.DAT` | 338,327,032 bytes |

SHA-256은 [펌웨어 식별 정보](../../data/firmware-manifest.json)에 기록한다. 파일 복사가 끝난 뒤 UFU 청크가 `DEND`까지 완전한지 확인하고 해시를 계산했다. 실행 중 파일의 크기와 수정 시각은 바뀌지 않았다. 두 파일 모두 `dat.readDat()`의 컨테이너 CRC 검사를 통과했다.

| 항목 | 값 |
| --- | --- |
| 도구 | [DavidBuchanan314/fwtool.py, a7iv](https://github.com/DavidBuchanan314/fwtool.py/tree/a7iv) |
| 커밋 | `3955d7890fc38daf942bb52827599bfe35de4a14` |
| 관련 변경 | [ma1co/fwtool.py PR #52](https://github.com/ma1co/fwtool.py/pull/52) |
| 실행 환경 | macOS, CPython 3.14.2, uv 0.13.5 |
| 런타임 의존성 | pycryptodomex 3.24.1, PyYAML 6.0.3 |

## 재현 명령

`inputs/`에 해시가 일치하는 두 파일을 준비한다. 다음 명령은 수정한 파일명을 사용한다. 실제 최초 실행에서는 이름 교환 전 파일명을 사용했다.

```sh
git clone --branch a7iv https://github.com/DavidBuchanan314/fwtool.py.git fwtool
git -C fwtool checkout 3955d7890fc38daf942bb52827599bfe35de4a14
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python pycryptodomex==3.24.1 PyYAML==6.0.3
.venv/bin/python fwtool/fwtool.py unpack -f inputs/A7R5_4.00.DAT -o artifacts/A7R5_4.00
.venv/bin/python fwtool/fwtool.py unpack -f inputs/A7R6_1.02.DAT -o artifacts/A7R6_1.02
```

패키지 버전은 이 실험을 재현하기 위해 고정했다. `pyinstaller`는 실행 파일 배포용 의존성이므로 이번 소스 실행에는 설치하지 않았다.

## 관찰

| 항목 | A7R V 4.00 | A7R VI 1.02로 추정되는 파일 |
| --- | --- | --- |
| UFU 매직 | `895546550d0a1a0a` | `895546550d0a1a0a` |
| DATV 페이로드 | `01000000` | `01000000` |
| FDAT 청크 헤더 오프셋 | `84` | `132` |
| FDAT 페이로드 크기 | `754525456` | `338326928` |
| 종료 코드 | `0` | `1` |
| 복호화 | `CXD90057_k8` | `No decrypter found` |
| 내부 모델 ID | `0x11030080` | 미확인 |
| 내부 버전 | `4.00` | 미확인 |

A7R V 파일에서 `firmware.fdat`, `firmware.tar`, `updater.img`, `config.yaml`과 재귀 추출 결과를 생성했다. `config.yaml`의 모델 ID와 버전이 PR의 A7R V 보고와 일치한다. 파일 크기는 [Sony A7R V 4.00 공식 정보](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm5/software/00292267)와 일치한다. 이 결과는 직접 확인했다.

작은 파일의 크기는 [Sony A7R VI 1.02 공식 정보](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm6/software/00413269)와 일치한다. 다만 복호화에 실패했으므로 내부 모델과 버전은 확인하지 못했다. A7R VI 1.02라는 분류는 공식 크기와 사용자 제공 맥락에 근거한 추정이다.

이 파일은 등록된 12개 복호화 후보 모두에서 첫 블록 체크섬 검사를 통과하지 못했다. 도구는 `No decrypter found`로 종료했고 추출 결과를 생성하지 못했다. 실행 중 생성한 빈 `firmware.fdat`는 성공 결과로 간주하지 않는다.

## 판정과 한계

해당 커밋은 확인한 A7R V 4.00 파일을 추출한다. A7R VI 1.02로 추정되는 입력은 현재 구현과 키로 추출하지 못했다. PR의 [2026-10-22 외부 보고](https://github.com/ma1co/fwtool.py/pull/52#issuecomment-6344060460)도 A7R VI 1.02의 키를 미확인 상태로 기록한다.

현재 실패만으로 키 변경과 블록 형식 변경을 구분하지 못한다. 공식 배포 파일과 SHA-256을 대조하지 않았으므로 같은 크기와 유효한 CRC만으로 배포 원본과의 동일성을 확정하지 않는다. 이 실험은 실기기 실행, 재패키징, 서명 우회나 설치를 검증하지 않았다.

## 다음 확인 항목

1. A7R VI 파일의 공식 배포 원본을 확보해 SHA-256을 대조한다.
2. 작은 파일의 FDAT 블록 구조와 기존 복호화 구현이 전제하는 형식을 비교한다.
3. A7R V의 추출된 업데이트 구성 요소에서 모델과 키 선택 과정을 조사한다. 다른 기종에도 같은 방식이 적용되는지는 별도로 검증한다.
